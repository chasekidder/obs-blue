# Phase 1: feature switches and OBS items (foundation)

Date: 2026-11-24
Branch: `improve/1-foundation` (base: `main`)

## Goal

Later phases add optional features (recording, upload, holding scene, branding, white-balance freeze, mic filters, claim highlighting, deck warnings). Each must be easy to turn on and off, must not change today's behavior while off, and must never break a stream. This phase adds the shared plumbing; it adds no feature.

## Rules every feature follows

1. **One switch per feature.** A config section `[<feature>]` with `enabled` plus its options. `default-config.toml` ships `enabled = false`; `site.example/site.toml` documents it, commented out. Switches are read once, at startup.
2. **Off means today's behavior.** A feature that is off only runs its `restore()`: at boot and on every OBS connect it undoes what an earlier run changed (camera controls back to auto, its OBS items disabled or hidden). Scenes are never deleted.
3. **OBS changes go through obs-websocket, idempotently**, never through the one-time seed.
4. **A broken feature cannot break the stream.** Every hook is bounded and best effort.
5. **Rollback safety.** No new controller states. New `state.json` / `status.json` fields are optional.

## Design

### Switches (`config.py`)

- `FEATURE_SECTIONS` lists the sections that are switches, in display order. This phase lists only the existing `ssn`; each later phase appends its own.
- `Config.features()` returns `{name: enabled}`.
- A non-boolean `enabled` (for example `"false"` in quotes) is logged and the default is used, so a typo can neither stop the controller nor turn a feature on by accident.

### Status

- `status.json` gets an optional `features` object (the switches the running controller loaded). An older image after `bootc rollback` ignores it.
- `stream-pilot status` prints a `features:` block, one `name: on|off` line each. A status file without `features` prints as before.
- `stream-pilot run` logs the switches once at startup.

### Feature objects (`features.py`)

`Feature(enabled)` with two hooks, both no-ops by default:

- `restore()`: called for features that are **off**, at boot and on every OBS connect. A feature whose restore only talks to OBS sets `restore_needs_obs` and is restored on the OBS connect only (at boot OBS's websocket may not be up yet; seen on the PC as a logged traceback).
- `obs_connected()`: called for features that are **on**, on every OBS connect.

Later phases add hook methods (`live_confirmed`, `stream_finished`, ...). The controller calls them through `_feature_hook(name, *args, timeout=...)`, which skips features that are off and logs (never raises) failures and timeouts. `run_hook` bounds one call by `HOOK_TIMEOUT_S` (10 s) unless the caller passes a tighter budget.

`app.build_features()` creates the feature objects; it returns an empty list in this phase.

### OBS connects

- `SimpleObsClient.add_connect_listener(fn)` calls `fn()` after every successful identify, including the transparent reconnect after OBS was restarted by systemd. `app.py` turns it into an `ObsConnected` event.
- The controller handles `ObsConnected` by starting one background sync task (never inline): enabled features get `obs_connected()`, disabled ones `restore()`. A reconnect while a sync runs makes it run once more afterwards.
- `SimpleObsClient.request(type, data)` sends any request. OBS refusals raise `ObsRequestFailed`, a `StepFailed("obs")` subclass that carries the obs-websocket status code (600 = not found).
- `SimpleObsClient.on_event(name, handler)` subscribes to further OBS events (used for scene changes in phase 6).

### OBS items helper (`obs_items.py`)

A feature declares what it needs: `Scene(name)`, `SceneItem(scene, source, kind=None, settings, transform)`, `Filter(source, name, kind, settings)`. `apply_items(obs, items, on)`:

- **on:** creates what is missing (scene, input with its scene item, scene item for an existing source, filter) with the declared settings, then enables / shows every item;
- **off:** disables / hides the declared items that exist and creates nothing;
- never changes an existing item's settings, transform or order, so the host's own OBS changes survive;
- applies each item on its own and logs a failing one, then continues; never raises.

### Image

`tests/image/smoke.sh` checks for `ffmpeg` with the `libopus` encoder, the PulseAudio input, the segment and Ogg Opus muxers, plus `rsync`, `ssh` and `ssh-keygen`. All come from the base image today; the check catches a base-image change.

## Tests

- `test_features.py`: switch listing and coercion, status formatting with and without `features`, hooks for on and off features, a failing and a hung feature still reach `READY`, reconnect during a sync, no OBS requests without features.
- `test_obs_items.py`: create, idempotence and the host's settings kept, off creates nothing, off disables, existing input reused, one failing item, transport failure, cancellation.
- `test_obs.py`: `request`, `ObsRequestFailed.code`, connect listeners, extra events.

## Out of scope

Any feature. The phase only changes behavior by adding a `features:` block to `stream-pilot status`.
