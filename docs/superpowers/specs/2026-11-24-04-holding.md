# Phase 4: holding scene before Go Live

Date: 2026-11-24
Branch: `improve/4-holding` (base: `improve/3-upload`)
Switch: `[holding] enabled` (default `false`), `mode = "studio" | "banner"` (default `"studio"`), `text` (default "Starting soon")

## Goal

Today the pre-roll streams the camera scene with the microphone for minutes before Go Live. Facebook does not air it, and the replay does not include it (phase 0 notes), but anything said in the room during setup still goes to Facebook. With this feature the pre-roll carries a holding scene without the microphone, and the camera scene goes on air when the live really starts.

## Microphone

Phase 0 found the microphone is a source inside each camera scene (not a global audio device). That is already the structure this needs: a scene without the microphone is silent, so audio follows the scene and there is never a mute state to forget. The feature creates its scenes without the microphone and never adds it; it changes nothing in the camera scenes.

## Studio mode (default)

- Before the pre-roll stream starts (every setup attempt, right before `StartStream`): create the "Holding" scene if missing (a dark color source and the text, centered), take Studio Mode off if it is on, put "Holding" on air and wait for the scene transition, turn Studio Mode on, then put the chosen camera scene (default: main) in the preview. OBS swaps preview and program when a transition ends, even to the same scene, so the order matters (seen on the PC: setting the program while in Studio Mode left "Holding" in the preview too).
- Camera keys before Go Live (states up to `GOING_LIVE`) put that camera's scene in the preview and remember it; the deck still shows the chosen camera and autofocus is set as today. If the host has put something else on air in OBS, the keys work as today.
- When Facebook confirms the live (the go-live flow's `LIVE` transition, not the key press): Studio Mode off (the program stays), then the previewed camera scene on air.

## Banner mode

Before the pre-roll: create "Starting Soon" if missing (the main camera's input with its transform copied from the main camera scene, a translucent bar and the text; no microphone), Studio Mode off, put it on air. Camera keys only choose the scene for later. At live confirmation the chosen camera scene goes on air.

## Always

- A holding scene is never put on air while live; camera keys while live switch the program as today.
- On resume in a live state, if a holding scene is on air or Studio Mode is on, Studio Mode goes off and a camera scene goes on air.
- After a long-press end the next setup puts the holding scene on air again.
- The scenes are created over obs-websocket only if missing (phase 1 helper) and never changed afterwards: the host may restyle them in OBS.
- Window layout is unchanged: OBS keeps the left column, the producer the right one. In Studio Mode with OBS's portrait layout, the program is shown above the preview (checked on the PC through the KVM).

## Off

No scene change before Go Live (today's behavior). The restore (boot and OBS connects) hides the items of both holding scenes, and if a holding scene is on air (the switch was on before), turns Studio Mode off and puts the main camera scene on air. Scenes are never deleted.

## Render cost (measured on the PC, dry run, 60 s each, pre-roll streaming)

| | Render time per frame | CPU | Skipped frames (render / output / stream) |
|---|---|---|---|
| Studio Mode off (today) | 0.89 ms avg, 1.14 ms max | 5.4 % | 0 / 0 / 0 of 1802 |
| Studio Mode on, Holding on air, Main Camera in preview | 1.65 ms avg, 2.09 ms max | 5.6 % | 0 / 0 / 0 of 1802 |

About 0.8 ms more per frame of a 33 ms budget, no lag, and switching was reliable after the ordering fix, so `studio` stays the default.

## Replay

The replay does not include the pre-roll (phase 0). It starts about 3 s after the Go Live press, and the camera goes on air when stream-pilot sees the confirmation, about 8 s after the press, so a replay starts with roughly 5-8 s of the silent holding card (measured: 7.5 s in a test-Group live).

## Robustness

All OBS work is in bounded feature hooks; a failing request is logged. A broken holding never blocks READY or Go Live (test with every OBS request failing).

## Rollback

No new states or state fields. An older image leaves the "Holding" / "Starting Soon" scenes in OBS unused.
