# Phase 3: upload the stream folders

Date: 2026-11-24
Branch: `improve/3-upload` (base: `improve/2-recording`)
Switch: `[upload] enabled` (default `false`)

## Goal

Get every stream's record off the PC (it is only on for streams and has one disk), without disturbing the live stream on a shared, sometimes congested uplink. No home server exists yet; the design assumes an SSH server with rsync.

## Behavior with the switch on

- **Timer.** `stream-pilot-upload.timer` (user unit, not enabled in the image) is started by stream-pilot at boot; its first run is 10 s later (the boot's catch-up), then 60 s after each run ends. `stream-pilot-upload.service` is a oneshot running `stream-pilot upload` with `Nice=19`, `IOSchedulingClass=idle`, `CPUWeight=idle`, `MemoryHigh=256M`. A lock file keeps it to one upload at a time.
- **What a run copies** (rsync over SSH, `--partial`, `--timeout=timeout_s`, `--bwlimit` from `bwlimit_kbps`, default 200 kbit/s ≈ 24 KiB/s, `--mkpath`):
  1. `status.json` to `<target>/_status/`, if it is fresh (stream-pilot is running): a heartbeat;
  2. every stream folder without a local `.uploaded` marker, the one still being written first, then newest first, to `<target>/<folder>/`:
     - the finished files: `stream.json`, `report.txt`, `journal.txt`, `audio/manifest.jsonl` and only the clips the manifest lists (never a clip still being recorded, never ffmpeg's segment list);
     - `comments.jsonl` with `--append` (it only grows; a partial last line on the server is completed next time);
     - `DONE` last, and only if everything else copied in this run; then the local `.uploaded` marker is written;
  3. new failure snapshots from `failures_dir` to `<target>/_failures/`;
  4. retention: local stream folders with `.uploaded` and a `DONE` older than `retention_days` (90) are deleted. A folder that was never fully copied is never deleted.
- **End of a stream.** After the comment capture stopped and the report is written: `stream_closed` writes `journal.txt` (`journalctl --user -u stream-pilot` since the pre-roll, or the Go Live press, or the folder's time); `stream_done` writes `DONE` (the recording feature does, or upload does when recording is off), stops a running timer run, and copies the heartbeat and this folder once, cut off after `final_timeout_s` (30 s). Then the power-off continues; the next boot finishes an interrupted copy.
- **SSH.** Key `~/.config/stream-pilot/upload_ed25519` (ed25519, no passphrase, mode 600), generated on first boot by `seed-obs` (OBS's pre-start step, like the obs-websocket password) or on first use. Host key pinned from `[upload] host_key` into `~/.config/stream-pilot/upload_known_hosts`, the only known_hosts file read (`StrictHostKeyChecking=yes`, `GlobalKnownHostsFile=/dev/null`). `BatchMode=yes`, `IdentitiesOnly=yes`, `ConnectTimeout=connect_timeout_s`, `ServerAliveInterval=5` × 3. Connections are shared for 60 s (`ControlMaster=auto`, socket in `$XDG_RUNTIME_DIR`), so one run is one SSH handshake.
- **`stream-pilot upload-key`** prints the public key and a suggested server line: `restrict,command="rrsync -wo <inbox dir>" <key>` (write-only, one directory), plus how to pin the host key.
- A config problem (no target, no host key, malformed target) is logged and copies nothing; it never raises.

## Behavior with the switch off

No timer, no copies, no journal, no `DONE` from upload. The restore stops the timer and a running upload (at boot and on OBS connects). `stream-pilot upload` run by hand says the switch is off. The key is still created on first boot, so `upload-key` works before the switch is turned on.

## End-flow budget

The final copy is bounded by `final_timeout_s` inside the end flow's 70 s budget (phase 2). `test_upload.py` runs the end flow with the recorder, the journal and the final copy all hung (scaled 1:100) and asserts it stays inside the power guard's window.

## Rollback

New files only (`.uploaded`, `journal.txt`, the key files); no new states or `state.json` fields. An older image has no timer; its controller ignores `[upload]`.

## Image

`stream-pilot-upload.service` and `.timer`; smoke test checks them (`systemd-analyze verify`), `stream-pilot upload --help`, `upload-key --help`; phase 1 checks `rsync` and `ssh`.
